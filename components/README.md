# Eidos Component Library

Eidos may contain a very large component library.

The rule is not "few components". The rule is:

> Capability-first, component-rich.

Components are implementations. Capabilities are semantic contracts.

Eidos may study and reproduce the useful behavior of mature ecosystems, but every Eidos-native component must obey Eidos contracts for:

- explicit state ownership;
- normalized events;
- deterministic props;
- accessibility;
- attention/motion semantics;
- renderer boundary;
- tests;
- LLM discoverability;
- documentation.

Eidos absorbs framework complexity instead of teaching it to the LLM.
