# Human UI review — Productive Workbench issue-card parity — 2026-10-20

## 目标与完成条件

Bring the opt-in Eidos `workbench` review-task issue list closer to the approved EVO-App-Platform BEX-01 V3 prototype. Each issue must read as a distinct, numbered Human decision, with enough visual separation to scan the issue types and an action button that remains easy to reach on phone widths. This change is presentation-only; it must not decide mappings, resolve ambiguous fields, discard source values, or execute Host commands.

Completion conditions: CSS remains scoped to `[data-eidos-task-presentation="workbench"]`; non-workbench task presentations remain unchanged; issue titles and action labels remain Host-owned; desktop and mobile layout remain keyboard-usable; the design-language test protects numbering and mobile action placement.

## 流程与步骤

The Host constructs issue objects from durable mapping and dry-run evidence. Eidos renders those objects in order and styles each item as a numbered card. On desktop, the issue number, issue content, and action share a row. On narrow screens, the action moves below the issue content instead of being squeezed into a narrow trailing column. The CSS does not add click handlers or alter form submission.

## 导航与信息架构

The issue card remains within the existing task overview and does not introduce a new route, workflow stage, or navigation surface. The Host continues to own the focus target and action label. The numbered badge is visual order only; it is not a severity, priority, or persistent issue ID.

## 视觉与颜色

Changed UI source: `src/design-language/productive-workbench-css.ts`.

Use Eidos spacing, border, radius, typography, foreground, background, and warning tokens. Cards receive a subtle warning-tinted border and a small numbered badge. The list becomes a gap-based stack rather than one continuous grey slab. The style is intentionally scoped to the workbench presentation; generic and decision-first task layouts retain their previous appearance. No fixed color palette or extra icon dependency is introduced.

## 记忆与注意力

Numbering makes the count and reading order apparent without requiring color alone. Each card keeps a concise title, explanation, and action together. The card number must never be interpreted as issue severity. A long title or description may wrap naturally; content is not truncated to force a screenshot-perfect row.

## 无障碍与跨年龄

The number is supplementary and does not replace the text title. Existing action buttons retain their native button semantics, keyboard focus treatment, and accessible name. On phone widths the action moves to a separate row with the same touch target; the grid does not shrink the action control to fit the text column. Existing contrast and system text-scaling tokens remain authoritative.

## 安全与数据修复

Eidos only changes rendering. It does not rewrite Host issue records, source columns, row numbers, mapping choices, Import Job state, or permissions. The source file remains the evidence authority. The visual number is generated by CSS and is not sent to the Host or persisted as business data. No import, retry, or commit action is added.

## 证据与剩余问题

Reference evidence reviewed on 2026-10-20:
- EVO-App-Platform approved V3 prototype PR #909: https://github.com/jiangxng/EVO-App-Platform/pull/909
- BEX-01 live Host issue-state screenshots and 390px/1280px browser evidence from the isolated synthetic fixture. The fixture demonstrates three different issue classes: ambiguous bank target, missing subject type in three rows, and an unresolved system-code column.
- Eidos design-language regression: `tests/design-language/design-language.test.mjs` asserts that the issue list has numbered badges and that mobile actions move to the second grid column.

The Platform currently supplies domain-specific titles and action labels; Eidos does not infer these. Remaining product-level parity work (file-type icon, exact upload/file card, workflow stepper, and bottom action bar) remains outside this CSS-only PR and must be reviewed separately. Physical iOS Safari and Android devices are not covered by this change.
